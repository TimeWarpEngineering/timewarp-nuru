# AddCheckUpdatesRoute() generated code references internal CheckUpdatesJsonSerializerContext (CS0122 for consumers)

## Description

`AddCheckUpdatesRoute()` produces generated code that does not compile in a consumer project (`CS0122`). Found by the task 523 consumer check (TimeWarp.Nuru 4.0.0-beta.5 from nuget.org, clean cache; evidence in `kanban/done/523-*/evidence/4.0.0-beta.5/` on branch `task/523-nuru-verification-skill-launch-and-drive-the-real`).

The public API is `AddCheckUpdatesRoute` in `source/timewarp-nuru/nuru-app-builder-extensions.updates.cs` (~line 29); its public contract says a consumer can call it. The generated code (`source/timewarp-nuru-analyzers/generators/emitters/check-updates-emitter.cs`) references `internal partial class CheckUpdatesJsonSerializerContext` (`source/timewarp-nuru/check-updates/check-updates-types.cs`, ~line 27), made internal by #358 (2026-01-14). Generated code lives in the consumer's assembly and can only use public surface, so the source's own public API and its emitter disagree. Likely broken in every release since, including 3.0.0 (unverified; confirm by installing 3.0.0 in a clean consumer).

Why tests did not catch it: `routing-21-check-updates-version-comparison.cs` passes only because `source/timewarp-nuru/internals-visible-to.g.cs` (generated by `runfiles/generate-internals-visible-to.cs`) grants InternalsVisibleTo to 258 repo assemblies, including `run-ci-tests`. See the sibling task on a consumer-compile test lane.
