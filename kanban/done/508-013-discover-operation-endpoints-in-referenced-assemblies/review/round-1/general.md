**Date:** 2026-10-21
**Scope reviewed:** branch `task/508-013-discover-operation-endpoints-in-referenced-assembl` vs `master` (implementation commit `500227a9` plus the audit commit). Generator, locator, extractor, JSON task, tests, sample 17, and `neutral-contracts.md`.

## Summary

A CLI can opt in to `[Operation]` and `[NuruRoute]` types from a referenced assembly with `[assembly: NuruEndpointAssembly(typeof(X))]` or with `Map<T>()` on one type. Extraction goes through the same symbol path as source types. Metadata members with no syntax use `default!` so the compiled initializer runs, `[DefaultValue]` feeds capabilities, and a positional parameter default is copied. Inaccessible nested handlers are dropped. The JSON task uses the same two opt-ins. `generator-59` (7) and `generator-60` (3) passed in this review. Two holes sit on paths those tests do not hit: diagnostic locations taken from another compilation's syntax, and a record constructor parameter with no explicit default that forces the member required.

## Issues

### Issue 1 — Severity: bug
- File: source/timewarp-nuru-analyzers/generators/extractors/operation-endpoint-extractor.cs:1015
- Description: `AttributeLocation` returns `attribute.ApplicationSyntaxReference.GetSyntax().GetLocation()` whenever that reference exists. A compiled DLL has no syntax, so the opt-in site (the fallback) is used and `generator-59` reports NURU_H008 cleanly. An IDE project reference is the other shape this change already guards in `ExtractPropertyDefaultValueFromSymbol`: the symbol's syntax tree is not in the consuming compilation. The attribute location is then outside this compilation. Roslyn 5.6 rejects that when the diagnostic is reported (`Reported diagnostic '{0}' has a source location in file '{1}', which is not part of the compilation being analyzed.`). NURU_H008, NURU_H009, and an invalid route pattern on a referenced type are enough to fail the generator. The route-location map itself stays on the opt-in site (`ExtractReferencedEndpoint` passes the `Map<T>()` or assembly-attribute location), so a referenced endpoint that produces no diagnostic is unaffected. The locator's `GetSyntax` on the assembly attribute is also in this compilation.
- Suggestion: If `compilation.ContainsSyntaxTree(reference.SyntaxTree)` is false, use the fallback location (the opt-in site). Pass the compilation into `AttributeLocation`. Add a generator test that feeds a `CompilationReference` (syntax present, tree not contained) and asserts the generator `Exception` is null and NURU_H008's location is the `Map<T>()` call.
- Status: open

### Issue 2 — Severity: bug
- File: source/timewarp-nuru-analyzers/generators/extractors/endpoint-extractor.cs:1253
- Description: `MetadataPropertyDefault` returns `ParameterDefault` for the first record constructor parameter whose name and type match the property. `ParameterDefault` returns an empty `PropertyDefault` when `HasExplicitDefaultValue` is false (`Code` null, `Display` null). A null code is the source-type signal for "no initializer": `TryDeriveSegment` sets `contractRequired` (`operation-endpoint-extractor.cs:303`), and `CommandConstructionEmitter` writes the member into the object initializer because null is not `default!`. That blocks the compiled initializer and drops `[DefaultValue]`. It is the right outcome for `record Q(string Name)` with no parameterless constructor, because that constructor really requires `Name` (`RefRecordQuery` in generator-59). It is the wrong outcome when a different parameterless constructor is the one `HasCallableParameterlessConstructor` selects (`operation-endpoint-extractor.cs:823`), for example `record Note(string Title) { public Note() : this("untitled") {} }`. Omission should run `new()`, which chains to `"untitled"`. The null code makes `--Title` required, so that default never runs. A parameter that does have an explicit default is copied, and generator-59's `Count = 7` path passes.
- Suggestion: Use a constructor parameter only when `HasExplicitDefaultValue` is true. When the constructor `TrySelectConstructorArguments` will actually call has a non-optional parameter of that name, keep the option required (the `record Q(string Name)` case). When the called constructor is parameterless, ignore other constructors' parameters that have no explicit default and use `default!` plus `[DefaultValue]`, so the compiled initializer runs. Cover both shapes in generator-59: primary parameter with no default stays required, and a parameterless constructor that chains a value stays optional with the member left out of the initializer.
- Status: open
