# DevCli source content never causes a consumer diagnostic: RCS1194 on, review suppressed rules

## Description

TimeWarp.Nuru.DevCli ships its code as source (`source/timewarp-nuru-devcli/content/any/**/*.cs`, 26 files).
Those files compile inside the consumer's project under the **consumer's** analyzer rules. Consumers have
their own rules. The goal is that DevCli's shipped source is never the cause of a consumer's warning or
error, whatever those rules are.

Evidence (2026-10-30, timewarp-architecture, taking DevCli 4.0.0-beta.8):

> Nuru's DevCli package ships a sealed exception class (PackageFeedUnreadableException) that is missing a
> constructor, so it trips Roslynator warning RCS1194

`PackageFeedUnreadableException` (`content/any/services/package-feed-lookup.cs:121`, added by 536) derives
from `HttpRequestException`. It has `()`, `(string)`, `(string, Exception)` and
`(string, Exception?, HttpStatusCode?)`, but most likely not
`(HttpRequestError, string?, Exception?, HttpStatusCode?)`. Confirm it by compiling with RCS1194 on.

Nuru never saw this because its `.editorconfig:390` sets `RCS1194.severity = none`. Architecture does not
set RCS1194, so the Roslynator default applies. Roslynk earlier hit IDE0290 from the same content files.

Steve 2026-10-30: "the point is that nuru cli that ships as source won't be the cause of the error. ok do both".

## Requirements

### 1. No suppression of DevCli source

Steve 2026-10-30: "i don't want us to supress the damn thing either so generate the constructor".

- **No** `// <auto-generated/>` headers, `#pragma warning disable`, `[SuppressMessage]`, globalconfig, or any
  other way of hiding DevCli content from consumer analyzers. The code itself must pass the rules.
- Add the missing `PackageFeedUnreadableException` constructor(s) so RCS1194 is satisfied. Confirm which base
  constructor is missing by compiling with RCS1194 on.

### 2. Nuru stops suppressing rules that are just unfixed violations

- Remove `dotnet_diagnostic.RCS1194.severity = none` (`.editorconfig:390`) and fix every violation it
  reports. That includes adding the missing `PackageFeedUnreadableException` constructor.
- Review the other 20 `severity = none` entries in `.editorconfig` (CA1034, CA1308, RCS1139-1142, RCS1181,
  RCS1021, RCS1238, RCS1045, RCS0051, RCS0052, RCS0036, RCS1123, RCS1124, RCS9001-9003, IDE0290, IDE1006).
  Classify each one as either:
  - **preference**: keep it, with a reason on the line if it lacks one. Examples are IDE0290, which is off
    per project preference, and RCS1045 (underscore fields, which the C# conventions forbid).
  - **unfixed debt**: re-enable it and fix the violations.

  Record the classification table in Results. If an entry's violations are too many to fix here, keep it
  suppressed and list it as a follow-up with its count.
- Don't change `[ganda.audit]` entries.

### Gates

- `ganda runfile cache --clear` before CI tests (DevCli content feeds runfiles).
- `dotnet run tests/ci-tests/run-ci-tests.cs` passes. The build passes with warnings as errors.
  `ganda repo audit` passes.
- Ships in the next DevCli beta (4.0.0-beta.9). Don't bump the version here.
