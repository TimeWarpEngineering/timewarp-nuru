# Find generated code that depends on internal types, and add a consumer-compile test lane without InternalsVisibleTo

## Description

Root cause class behind the `AddCheckUpdatesRoute()` CS0122 defect: `source/timewarp-nuru/internals-visible-to.g.cs` (generated by `runfiles/generate-internals-visible-to.cs`) grants InternalsVisibleTo to 258 repo assemblies, including the CI test assembly. Any generated code that references an internal type of a TimeWarp.Nuru* assembly therefore compiles in every repo test but fails in a real consumer. Found by the task 523 consumer check (TimeWarp.Nuru 4.0.0-beta.5 from nuget.org, clean cache; evidence in `kanban/done/523-*/evidence/4.0.0-beta.5/` on branch `task/523-nuru-verification-skill-launch-and-drive-the-real`).

Generated code is part of the consumer's assembly, so the public API surface of the runtime packages is the only legitimate dependency. The source (emitters plus their Purpose/Design regions) defines what the generator may emit; this task makes that checkable.

## Goal (implementer restatement)

Generated code compiles into the consumer's assembly, so it may name only the public surface of the
TimeWarp.Nuru* runtime assemblies. Repo tests cannot see a breach because `internals-visible-to.g.cs`
grants InternalsVisibleTo to every test assembly. Done means:

- Every name the emitters write into generated code is checked against the runtime's declared
  accessibility. Each internal reference is fixed or filed as a task.
- A test lane compiles representative output from every emitter under an assembly name that no grant
  lists, so a CS0122 (or CS0117) fails CI. It runs in `./bin/dev test` and in the CI test stages.
- The narrowing question for the blanket grant is decided and recorded. The generator script and
  generated files change only if the grant is narrowed.
- A `#region Design` note states the consumer-surface rule at the generator entry.
- CI tests are green after a runfile cache clear.

### InternalsVisibleTo decision

Keep the blanket grant to test assemblies; do not narrow. Reasons: (1) the consumer surface is now checked
directly by an ungranted compilation, which is what narrowing tried to approximate; (2) most of the 349 test
assemblies, including the CI multi-mode `run-ci-tests` assembly, are white-box tests of internal types, so
narrowing would have to audit each file and would still leave every granted test blind to a consumer break;
(3) `devcli-consumer-check` stays excluded (528, 562). The decision is recorded in
`runfiles/generate-internals-visible-to.cs`. The regeneration on this branch only added stems that were already
missing (generator-73, generator-74, mcphost-06) plus generator-75. The grant was not narrowed.

## Results

### Changes

- `tests/timewarp-nuru-tests/generator/generator-75-consumer-surface-no-ivt.cs` (new) is the consumer-compile
  lane. It is Roslyn-hosted and compiles in memory as `Gen75ConsumerApp`, a name no `InternalsVisibleTo` on
  TimeWarp.Nuru, .Daemon, or .McpHost lists (asserted first). It runs the Nuru generator and the System.Text.Json
  generator together, with a stand-in for the JSON contexts the TimeWarp.Nuru.Build task writes in a real build.
  It requires zero compile errors. Six cases between them reach every emitter: fluent routes (typed params,
  enums, options, aliases, catch-all, custom converter, method groups, async, return kinds, groups, help,
  version, capabilities, `--json-args`, unknown options); endpoints, services, and behaviors (`Map<T>` command
  classes, nested handlers with ctor DI, global, filtered, and `Implements<T>` behaviors, singleton, transient,
  scoped, command-scoped, and session-scoped services, typed HttpClient, configuration and IOptions, logging,
  telemetry); REPL, completion, check-updates, and runtime Microsoft DI; operation endpoints (OneOf with
  SharedProblemDetails, problem and verbatim renderers, direct invoke); daemon serve and MCP routes. Each case
  also asserts emitter markers, so a builder change cannot silently drop the path it covers. Errors in
  generated code print the offending generated line.
- CI wiring: `tests/ci-tests/Directory.Build.props` excludes it from multi-mode (CS0433, like generator-65).
  `tests/ci-standalone/run-standalone-tests.cs` runs it and prebuilds the daemon and mcphost projects before
  the parallel runs.
- `source/timewarp-nuru-analyzers/generators/nuru-generator.cs` gets a `#region Design` paragraph on the
  consumer-surface rule.
- `runfiles/generate-internals-visible-to.cs` records the keep-the-grant decision. The regenerated
  `internals-visible-to.g.cs` files (nuru, parsing, mcp) add the generator-73, 74, and 75 and mcphost-06 stems.
- Filed: 583 (value-type return null checks) and 584 (ConstraintAlias routes). Both are published to-do.
- Negative check (manual, reverted): with `NuruUnknownOption.IsOptionLike` made `internal`, generator-75
  failed 4 of 6 cases with `CS0117 'NuruUnknownOption' does not contain a definition for 'IsOptionLike'` at
  each generated call site. The lane catches a member hidden from consumers. A hidden *type* reports CS0122.
