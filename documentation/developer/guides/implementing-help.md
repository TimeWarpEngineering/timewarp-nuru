# Implementing Help Commands in TimeWarp.Nuru

This guide demonstrates various approaches to implementing help functionality in your TimeWarp.Nuru CLI applications, from simple manual help to sophisticated automatic help generation.

## Overview

> **Note:** `--help` / `-h` help is built in and generated by the source generator for every app; use `ConfigureHelp(Action<HelpOptions>)` to customize it. The manual routes below are for fully custom help output.

TimeWarp.Nuru provides flexible options for implementing help functionality:

1. **Manual Help Routes** - Define custom help commands with full control over formatting
2. **Contextual Help** - Add help for specific commands (e.g., `add help`)
3. **Built-in Help** - Generated automatically; customize with `ConfigureHelp`
4. **Standard Conventions** - Support `--help`, `-h`, and `help` patterns

## Basic Help Implementation

### Simple Help Command

The most straightforward approach is to add a dedicated help route:

```csharp
NuruAppBuilder builder = NuruApp.CreateBuilder();

// Basic help command
builder.Map("help")
  .WithHandler(() => Console.WriteLine(
    "MyApp - A sample CLI application\n" +
    "\n" +
    "Commands:\n" +
    "  add <x> <y>       Add two numbers\n" +
    "  multiply <x> <y>  Multiply two numbers\n" +
    "  help              Show this help message"
))
  .AsCommand()
  .Done();

// Also support --help convention
builder.Map("--help")
  .WithHandler(() => Console.WriteLine("Use 'help' for available commands"))
  .AsCommand()
  .Done();
```

### Help with Descriptions

Enhance readability by adding descriptions when registering routes:

```csharp
builder.Map("add {x:double} {y:double}")
  .WithHandler((double x, double y) => Console.WriteLine($"{x} + {y} = {x + y}"))
  .WithDescription("Add two numbers together")
  .AsCommand()
  .Done();

builder.Map("multiply {x:double} {y:double}")
  .WithHandler((double x, double y) => Console.WriteLine($"{x} × {y} = {x * y}"))
  .WithDescription("Multiply two numbers")
  .AsCommand()
  .Done();
```

## Contextual Help Commands

Provide detailed help for specific commands:

```csharp
// Command-specific help
builder.Map("deploy help")
  .WithHandler(() => Console.WriteLine(
    "Usage: myapp deploy <environment> [options]\n" +
    "\n" +
    "Deploy application to the specified environment\n" +
    "\n" +
    "Arguments:\n" +
    "  environment    Target environment (dev, staging, prod)\n" +
    "\n" +
    "Options:\n" +
    "  --version      Version to deploy (default: latest)\n" +
    "  --dry-run      Preview changes without deploying\n" +
    "\n" +
    "Examples:\n" +
    "  myapp deploy prod\n" +
    "  myapp deploy staging --version 1.2.3\n" +
    "  myapp deploy dev --dry-run"
))
  .AsCommand()
  .Done();

// The actual command
builder.Map("deploy {env} --version {version?} --dry-run")
  .WithHandler((string env, string? version) => DeployDryRun(env, version))
  .AsCommand()
  .Done();
```

## Automatic Help Generation

### Built-in Help

Every app gets `--help` / `-h` generated at compile time from your registered routes and their descriptions. No setup is required:

```csharp
NuruApp app = NuruApp.CreateBuilder()
  .Map("status")
    .WithHandler(() => "OK")
    .WithDescription("Show application status")
    .AsQuery()
    .Done()
  .Map("deploy {env}")
    .WithHandler((string env) => Console.WriteLine($"Deploying to {env}"))
    .WithDescription("Deploy to environment")
    .AsCommand()
    .Done()
  .Build();

// myapp --help          lists every route with its description
// myapp deploy --help   shows help for the deploy route
```

### Customizing Built-in Help

`ConfigureHelp(Action<HelpOptions>)` filters what the generated help lists:

```csharp
NuruApp app = NuruApp.CreateBuilder()
  .ConfigureHelp(options =>
  {
    options.ShowPerCommandHelpRoutes = false;    // hide "<command> --help" entries (default)
    options.ShowReplCommandsInCli = false;       // hide exit, quit, history, ... in CLI help (default)
    options.ShowCompletionRoutes = false;        // hide __complete and friends (default)
    options.ExcludePatterns = ["*-debug", "*-internal"];  // wildcard exclusions
  })
  .Map("status")
    .WithHandler(() => "OK")
    .AsQuery()
    .Done()
  .Build();
```

See [Auto-Help](../../user/features/auto-help.md) for the user-facing behavior.

### Custom Help Output

For fully custom output, define your own help route. A user-defined route is matched before the built-in flags, so it replaces the generated output for that pattern:

```csharp
NuruApp app = NuruApp.CreateBuilder()
  .Map("help")
    .WithHandler(() => Console.WriteLine(CustomHelpFormatter.Render()))
    .AsQuery()
    .Done()
  .Build();
```

The generated help text is not exposed as an API, so a custom route builds its own text from information your app already has (for example a static list of command descriptions):

```csharp
public static class CustomHelpFormatter
{
    private static readonly (string Pattern, string Description)[] Commands =
    [
      ("deploy <env>", "Deploy to environment"),
      ("config get <key>", "Get configuration value"),
      ("config set <key> <value>", "Set configuration value")
    ];

    public static string Render()
    {
        StringBuilder sb = new();
        sb.AppendLine("MyApp CLI v1.0.0");
        sb.AppendLine();
        foreach ((string pattern, string description) in Commands)
        {
            sb.AppendLine($"  {pattern,-30} {description}");
        }

        return sb.ToString();
    }
}
```

## Advanced Help Patterns

### Topic-Based Help Command

For applications with topic-based help:

```csharp
builder.Map("help {topic?}")
  .WithHandler((string? topic) =>
  {
    if (string.IsNullOrEmpty(topic))
    {
      Console.WriteLine("Topics: deploy, config");
    }
    else
    {
      ShowTopicHelp(topic);
    }
  })
  .AsQuery()
  .Done();

static void ShowTopicHelp(string topic)
{
  switch (topic)
  {
    case "deploy":
      Console.WriteLine("Usage: myapp deploy <environment>");
      break;
    case "config":
      Console.WriteLine("Usage: myapp config get <key> | config set <key> <value>");
      break;
    default:
      Console.WriteLine($"No help available for '{topic}'");
      break;
  }
}
```

### Version and Help Integration

Combine version information with help:

```csharp
builder.Map("--version")
  .WithHandler(() =>
{
    Console.WriteLine("MyApp version 1.2.3");
    Console.WriteLine("Copyright (c) 2025 MyCompany");
})
  .AsCommand()
  .Done();

builder.Map("help")
  .WithHandler(() =>
{
    Console.WriteLine("MyApp v1.2.3 - CLI Application");
    Console.WriteLine("Usage: myapp [command] [arguments] [options]");
    Console.WriteLine();
    Console.WriteLine("  add <x> <y>   Add two numbers");
    Console.WriteLine();
    Console.WriteLine("For more information, visit: https://myapp.com/docs");
})
  .AsCommand()
  .Done();
```

## Best Practices

### 1. Support Multiple Help Patterns

Users expect different help invocation patterns:

```csharp
// Support all common help patterns
Action helpAction = () => ShowHelp();

builder.Map("help")
  .WithHandler(helpAction)
  .AsCommand()
  .Done();
builder.Map("--help")
  .WithHandler(helpAction)
  .AsCommand()
  .Done();
builder.Map("-h")
  .WithHandler(helpAction)
  .AsCommand()
  .Done();
builder.Map("-?")
  .WithHandler(helpAction)
  .AsCommand()
  .Done();

// Also support help as a fallback
builder.Map("{*args}")
  .WithHandler((string[] args) =>
{
    if (args.Length == 0)
    {
        ShowHelp();
    }
    else
    {
        Console.WriteLine($"Unknown command: {string.Join(' ', args)}");
        Console.WriteLine("Use 'help' to see available commands");
    }
})
  .AsCommand()
  .Done();
```

### 2. Provide Meaningful Descriptions

Always include descriptions when registering routes:

```csharp
// Good: Includes description
builder.Map("backup {path} --compress")
  .WithHandler(BackupWithCompression)
  .WithDescription("Create a compressed backup of the specified path")
  .AsCommand()
  .Done();

// Better: Detailed description
builder.Map("restore {backup} --target {path?}")
  .WithHandler(Restore)
  .WithDescription("Restore from backup file. Target defaults to original location")
  .AsCommand()
  .Done();
```

### 3. Group Related Commands

Organize commands logically:

```csharp
// Database commands
builder.Map("db migrate")
  .WithHandler(DbMigrate)
  .WithDescription("Run database migrations")
  .AsCommand()
  .Done();
builder.Map("db seed")
  .WithHandler(DbSeed)
  .WithDescription("Seed the database")
  .AsCommand()
  .Done();
builder.Map("db reset")
  .WithHandler(DbReset)
  .WithDescription("Reset database to initial state")
  .AsCommand()
  .Done();

// User management
builder.Map("user create {email}")
  .WithHandler(CreateUser)
  .WithDescription("Create a new user")
  .AsCommand()
  .Done();
builder.Map("user list")
  .WithHandler(ListUsers)
  .WithDescription("List all users")
  .AsCommand()
  .Done();
builder.Map("user delete {id}")
  .WithHandler(DeleteUser)
  .WithDescription("Delete a user")
  .AsCommand()
  .Done();
```

### 4. Include Examples in Help

Show practical usage examples:

```csharp
builder.Map("help examples")
  .WithHandler(() =>
{
    Console.WriteLine("Examples:");
    Console.WriteLine();
    Console.WriteLine("  # Deploy to production");
    Console.WriteLine("  myapp deploy prod --version 1.2.3");
    Console.WriteLine();
    Console.WriteLine("  # Backup with compression");
    Console.WriteLine("  myapp backup /data --compress");
    Console.WriteLine();
    Console.WriteLine("  # Configure API endpoint");
    Console.WriteLine("  myapp config set api.url https://api.example.com");
})
  .AsCommand()
  .Done();
```

### 5. Handle Help Errors Gracefully

Provide helpful feedback for invalid help requests:

```csharp
builder.Map("help {command}")
  .WithHandler((string command) =>
{
    string[] known = ["deploy", "config", "backup"];

    if (!known.Contains(command))
    {
        Console.WriteLine($"No help available for '{command}'");
        Console.WriteLine();
        Console.WriteLine("Available commands:");

        foreach (string name in known)
        {
            Console.WriteLine($"  {name}");
        }
    }
    else
    {
        Console.WriteLine($"Usage: myapp {command} [options]");
    }
})
  .AsQuery()
  .Done();
```

### 6. Consider Output Formatting

Make help output easy to read:

```csharp
public static class HelpFormatter
{
    public static void ShowCommandHelp(string command, string description,
        string[] arguments, (string name, string desc)[] options)
    {
        Console.WriteLine($"\n{command}");
        Console.WriteLine(new string('-', command.Length));
        Console.WriteLine(description);

        if (arguments.Length > 0)
        {
            Console.WriteLine("\nArguments:");
            foreach (string arg in arguments)
            {
                Console.WriteLine($"  {arg}");
            }
        }

        if (options.Length > 0)
        {
            Console.WriteLine("\nOptions:");
            foreach ((string name, string desc) in options)
            {
                Console.WriteLine($"  {name,-20} {desc}");
            }
        }

        Console.WriteLine();
    }
}
```

## Summary

TimeWarp.Nuru provides flexible help implementation options:

- **Manual Help**: Full control over formatting and content
- **Built-in Generation**: `--help` is generated for every app; tune it with `ConfigureHelp`
- **Contextual Help**: Provide detailed help for specific commands
- **Mixed Approaches**: Combine automatic and manual help for best results

Choose the approach that best fits your application's needs and user expectations. For simple CLIs, manual help may suffice. For complex applications with many commands, leverage automatic help generation with custom enhancements where needed.
