## Summary

`WithNuruTools` is an extension on `IMcpServerBuilder`, and its XML example is the ASP.NET chain the doc already shows, so the pattern is supported and the doc stays. The generator used to start an IR app for every method named `CreateBuilder`. `IsNuruAppCreateBuilder` now requires the bound method's containing type to be `TimeWarp.Nuru.NuruApp`. An unbound call falls back to `CreateBuilderLocator`, which matches only the syntax `NuruApp.CreateBuilder(...)`. Any other `CreateBuilder` falls through to `HandleNonDslMethod`. That ignores a receiver that is not an IR builder, so `builder.Services.AddMcpServer()` is not `NURU_S999`. `DispatchBuild` already returns without recording a Nuru app when the receiver is not an `IrAppBuilder`, and `BuildLocator.IsConfirmedBuildCall` still requires a return type named `NuruApp`, so the host `Build()` does not start extraction.

The regression file puts a stand-in `CreateBuilder` (not `NuruApp`) and the real `AddMcpServer()` + `WithNuruTools` in the same method as a Nuru app. McpHost tests compile with the analyzer (`tests/Directory.Build.props`), and `tests/ci-tests/Directory.Build.props` globs this directory, so the file is in the CI assembly. `AddMcpServer` is the `ModelContextProtocol` 2.4.0 extension the McpHost package already references. `## Results` records `./bin/dev build`, `./bin/dev test`, `ganda repo audit`, and a Web SDK probe of the doc snippet.
