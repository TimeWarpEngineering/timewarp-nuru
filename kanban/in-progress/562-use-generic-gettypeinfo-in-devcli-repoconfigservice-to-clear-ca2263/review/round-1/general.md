## Summary

`RepoConfigService.Parse` no longer calls `GetTypeInfo(typeof(RepoConfig))`. It deserializes with `JsonContext.RepoConfig` on a `DevCliJsonContext` built with the `.jsonc` options (comments, trailing commas, case-insensitive names). That stays on the source-generated resolver: the context's `TypeInfoResolver` is `DevCliJsonContext`, and a harness parse of the legacy config (comment, unknown `checkVersionStrategy`, lowercase `packages`, trailing comma) returned `TimeWarp.Nuru,TimeWarp.Nuru.Analyzers`. `GetTypeInfo<T>()` exists on .NET 11.0.0-rc.3 and not on the net10.0 ref assembly, so the task's suggested generic call would not compile here. The only `GetTypeInfo` left under DevCli content is the comment. The new net11 consumer check imports the shipped props, turns warnings into errors, and skips `.editorconfig`; CA2263 and RCS1194 are not in its `NoWarn`. CI runs that check on the samples leg, which the required `ci` job already demands. The generated `RepoConfig` getter still calls `Options.GetTypeInfo(typeof(...))`, inside a file marked `<auto-generated/>`, which is why architecture reported the user line and not the generator.
